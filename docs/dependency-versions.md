# Dependency compatibility

The current .NET stack combines GA runtime/SDK builds in containers and CI (`11.0.0-resolute-chiseled` / `11.0.100-resolute`, `Microsoft.AspNetCore.OpenApi` `11.0.0`, `Microsoft.AspNetCore.Mvc.Testing` `11.0.0`, CI `dotnet-version: '11.0.100'`) with `global.json` pinning SDK **11.0.100-rc.2.26504.105**. EF Core, Relational, Design, and InMemory use **11.0.0-rc.3.26522.148** with Npgsql EF provider **11.0.0-rc.3**, while `.config/dotnet-tools.json` pins `dotnet-ef` at **11.0.0-rc.2.26504.105**. The Npgsql provider requires a matching EF major/prerelease cohort; update EF Core and Npgsql together when upgrading.

The API and test projects commit NuGet lockfiles. CI and API container builds use locked restore; after an intentional package update, refresh both locks locally and verify `dotnet restore api/src/RecipeApi.Tests/RecipeApi.Tests.csproj --locked-mode`. No database schema or PostgreSQL major-version migration is part of this dependency update.

Use Node **26.13.1** from `.nvmrc` (`pwa/package.json` allows `>=26.12.0 <27`) and npm **11.21.1**, then `npm ci` in `pwa/`. CI, setup tasks, and PWA images use the same versions. npm 12.2.0 was not selected because its default URL-fetch policy rejected the existing Tailwind WASM tarball during clean resolution; replacement can be reconsidered when that dependency path installs normally.

ESLint stays at **9.39.5** because Next's imported lint plugins exclude ESLint 10 in their peer ranges. TypeScript stays at **6.0.3** because `typescript-eslint` requires `<6.1.0`. Vitest and `@vitest/coverage-v8` pin **^5.1.1**. OpenSpec CLI (`@fission-ai/openspec`) is installed unpinned in local setup and CI; Task **3.54.0** and PyYAML **6.0.3** remain current. Kiota CLI **1.36.1** remains current; its TypeScript runtime packages align at `^1.0.0-preview.114`.

Container updates retain PostgreSQL **18** and Ubuntu **resolute**. The migration image uses PostgreSQL **18.7-trixie** and sqldef **3.11.30**; the database uses pgvector **0.8.7-pg18-trixie**. Traefik **v3.7.19**, cloudflared **2026.11.1**, and Alpine **3.23** are pinned in the Compose stack and release template. The PDF renderer and its matching notices stay unchanged because `PDFtoImage` **5.4.0** is the latest stable release. The Lambda adapter remains at **1.1.0**; deployment/release behavior is not changed.

These versions were checked against official NuGet/npm metadata, Microsoft's .NET release metadata/MCR tags, and publisher Docker Hub tags. A successful restore alone does not establish runtime compatibility: API/PostgreSQL tests, browser tests, generated-client parity, and the container smoke gate remain required before publication to `main`.

The EF/Npgsql provider cohort also keeps a bounded application adjustment: recipe-import attempt-start and success use parameterized PostgreSQL updates (`api/src/RecipeApi/Services/RecipeImportReportService.cs`) because the provider cannot translate their array-membership expressions. The updates remain atomic and retain recipe and workflow-attempt guards. Existing report behavior, status mapping, and schema are preserved.
