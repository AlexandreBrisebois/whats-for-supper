## Required local source and qualification record

Task1.1 authors a small proposed UTF-8 JSON vocabulary and pins the actual reviewed format version, release revision and raw SHA256; no vocabulary JSON/ID/hash is invented by this planning edit. Each accepted food has a stable app ID, food revision, EN/FR labels or explicit missing label, full-phrase exact aliases with locale/match key/relation, purchase qualifiers and local provenance. Retain authoring model identifier/revision/date, reviewed document/revision/date and exact relation decision. A local revision/hash/source reference is sufficient; do not fabricate external codes/citations or treat model confidence as semantic validation.

Start with fresh bulb onion, fresh tomato and canned tomato. Review literal preparation variants individually; no generic adjective stripping. The adversarial corpus records exact, rejected, ambiguous and unmapped decisions separately, including échalote, poivron/piment, coriander leaf/seed, salted/unsalted butter, cream percentages, combined seasonings, alternatives, unknown regional units and package forms. Same-key active collisions reject adoption; uncertain terms remain source-named. Report coverage and false merges without inventing a performance/accuracy threshold; no coverage score excuses a purchase distinction collapse.

The reviewed adoption/affected-set/reversal manifest binds prior/new revisions and hashes, changed IDs/labels/aliases/qualifiers, affected saved mappings/rows, private protections and manual-category conflicts. Model authoring supplies candidates; exact relation review plus executed producer/consumer/recovery evidence establishes what the app may publish. Global release review is distinct from household private correction and does not grant external data authority.

## Persisted authority and offline recovery

Store versioned UTF-8 JSON durably on disk through the existing storage/atomic-publication owner. The reviewed draft is initial installation input; persisted/restored JSON and every referenced retained release are authoritative thereafter. Restart, read, recompute and restore do not call AI, translate, download, silently reseed, overwrite a different valid file or regenerate missing referenced data. Expected-revision/hash replacement and missing/corrupt/unsupported data fail closed.

Full backup must capture the actual JSON plus dependent mapping/content revisions and protected household overrides under a coherent source fence. Full restore preflight validates format/hash/membership before writes and restores exact accepted bytes; archive record types alone do not implement this ordinary snapshot path. Test full backup→isolated restore→re-export, restart/provider unavailability, stale/different vocabulary, lost/interrupted file publication and file/DB races. Recipe source provenance and human protection remain distinct from model vocabulary provenance.

The [migration companion](../migrate-canonical-recipe-model/design.md) owns preserving all plans/events and rebuilding all lists; only its migration epoch permits bulk grocery check/baseline reset. Manual extras/corrections/history remain protected, with no empty-list gate or prior-operation allowance. See [design](design.md) and [tasks](tasks.md) for the common producer, scopes and actual acceptance obligations.
