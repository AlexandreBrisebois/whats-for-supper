## Decisions and Tradeoffs

1. Derive Home's card directly from the shared session, not Planner selection, scheduled days or a second local voting model. Request a coalesced session refresh on Home entry so initial hydration does not depend on successful SSE construction. Reuse the layout stream thereafter and the same refresh action for Retry. Add no poller or additional stream subscription.
2. Retain the existing Home card location, warmth and touch-sized primary action. Collecting uses neutral week-independent copy ("The family is voting") and Vote Now. Converged uses exactly "Menu's In" and "See your matches". Use a Home-specific headline key if sharing Discovery's key would change its capitalization or punctuation. Remove the misleading recipe-day count. Suggested supporting copy: "Your matches are ready to review and save." Do not claim that the plan is saved, locked or voting closed.
3. Remove dismissal while a round is open. Round-scoped dismissal is a credible quieter alternative, but would still violate the user's request to show the invitation whenever voting is open. No dismissal state is needed. Reopened rounds follow their new authoritative identity rather than inheriting completion or suppression from an earlier round.
4. For status `unknown` or initial `loading`, show compact "Checking voting…" with no round CTA. While rechecking, retain the last-known card but disable its round CTA and show checking feedback. On `unavailable`, retain that context with "Voting status unavailable" and Retry; without a snapshot show only that compact status. A valid `ready` snapshot restores the current CTA or removes an unowned invitation. This trades brief action interruption for honest freshness and recovery. No browser-age TTL or new freshness state machine is proposed.
5. At activation, read the currently accepted, usable `ready` session; capture its round and absolute Monday once. A state change already accepted must update or remove the action. For converged, set Planner tab and navigate to `/planner?weekOffset=0&referenceWeekStartDate=<captured Monday>`. Do not recompute a relative offset from the browser date. A server close racing after activation is handled by existing destination reconciliation; navigation grants no mutation rights and promises no atomic read across clients.

These are explicit proposed review defaults, not hidden implementation choices. Alex's approval is required before applying this draft. If any default changes, reconcile the delta and tasks first.

## First Observable Slice

Home entry → real `refreshSession`/generated `GET /api/discovery/session` consumer → accepted collecting snapshot for this week → Home Vote Now → Discovery. In a focused browser test, double only the HTTP/stream boundary with schema-compliant fixtures; keep the actual Home/store/layout seams. Assert next week closed, unrelated Planner selection, no dependence on recipe-bearing schedule days, no dismissal, and preserved library links. No backend change is required; mocked browser acceptance does not establish real database or device qualification.

Extend that same slice through convergence → Home matches action → absolute Planner week and meal-plan tab. Preserve quick convergence, pending suggestions, existing saved meals and explicit existing closure behavior. Do not change backend thresholds, Discovery completion logic or Planner suggestion presentation.

## State, Concurrency and Recovery

Reuse accepted session revisions and incarnations; Home must not compare wall clocks, derive convergence from local vote counts, copy suggestion arrays or relax existing stale-frame guards. Read failures retain shared last-known data but never establish current closed or converged state. Retry, reconnect and mobile resume converge through the existing store. A new round must not inherit the prior round's converged action. Missing identity/week is unavailable for Home navigation and offers Retry; inspect whether existing rejected-frame behavior already supplies this signal before making any narrowly necessary change.

Test invariants: every usable ready collecting/converged snapshot maps to the appropriate action independently of week selection; unowned maps to none; non-ready never offers an enabled round action; navigation retains the captured Monday across date rollover; handoff triggers no assignment, lock or close request. Cover representative boundaries with existing test tools; no new property-testing framework is needed.

## User Experience and Design Review

Benefit: a household can resume the vote from Home and leave quickly for useful matches once enough agreement exists. One familiar card and one phase-appropriate action reduce interpretation and preserve the existing quick convergence win. Reuse Solar Earth tokens, semantic controls, focus visibility and reduced-motion behavior; keep Tonight usable during status work. Verify wrapping, reachable controls and English/French meaning on iPad, iPhone and Pixel Phone layouts. Exact approved English Home headline has no exclamation mark; do not silently inherit Discovery's different styling/copy.

Trade-offs: the persistent invitation occupies Home space, and temporarily disabled actions can feel cautious during a reconnect. Both are smaller and clearer changes than dismissal bookkeeping or another transport lifecycle. Avoid an extra modal or full-screen celebration on Home.

Concern for Alex's review: "Menu's In" can imply a finished, saved menu, while the accepted handoff still has suggestions waiting for explicit saving and voting closure. Keep the headline Alex chose and qualify it with the supporting sentence above. This draft interprets "suggestions waiting to be closed" as an invitation to review/save and explicitly close in the existing Planner journey, never an automatic close on navigation. If Alex intends automatic closure, that requires a changed approved behavior and a separate mutation design before application.

Baseline caution: the local older recipe-discovery spec still describes a celebration without a CTA. Current main's recipe-discovery spec has already been updated to the green success card and See your matches action, agreeing with current main's Discovery source. Use that current-main evidence; do not manufacture a discrepancy or alter Discovery in this Home change. Home's approved exact headline and proposed supporting sentence are intentionally local to Home.

## Compatibility, Rollout and Reversal

No contract, data migration, feature flag or transport change. Use existing `GET /api/discovery/session` response fields and `voting_session_updated` frames. Reverting the eventual Home-only implementation restores the old invitation behavior without data repair. Publication of this draft is review only; implementation, tests, merge, deployment and live mutations remain unperformed.
