Existing installations upgrade via idempotent DDL in [compatibility.sql](../../../../api/database/compatibility.sql#L139-L163) before `sqldef` applies `schema.sql` ([Dockerfile](../../../../api/database/Dockerfile), [migrate.sh](../../../../api/database/migrate.sh)). - **API & OpenAPI contract:** [specs/openapi.yaml](../../../../specs/openapi.yaml#L2340-L2694) defines inline member schemas on `GET /api/family`, `POST /api/family`, `GET /api/family/me`, `PUT /api/family/{id}`, and `PUT /api/family/{id}/preferences` (plus `400`/`404` on preferences). - **PWA API client, store & E2E mocks:** Kiota generates `pwa/src/lib/api/generated/api/family/{index.ts,me/index.ts,item/index.ts,item/preferences/index.ts}` from `specs/openapi.yaml`. [family.ts](../../../../pwa/src/lib/api/family.ts) adapts generated responses into [domain.ts](../../../../pwa/src/types/domain.ts) `FamilyMember`. [familyStore.ts](../../../../pwa/src/store/familyStore.ts#L54-L169) owns `updateMemberPreferences`, using a per-member `preferenceSaveGeneration` map to discard stale responses and roll back only changed keys on error. [builders.ts](../../../../pwa/src/testing/builders.ts#L156-L165) and [mock-api.ts](../../../../pwa/e2e/mock-api.ts#L591-L700) provide the stateful family mock for Playwright.
- **Theme, root boot & Profile UI:** Tailwind CSS v4 (`@tailwindcss/postcss`) compiles `@theme` in [globals.css](../../../../pwa/src/app/globals.css), mirrored by [tailwind.config.ts](../../../../pwa/tailwind.config.ts) and verified by [tokens.test.ts](../../../../pwa/src/test/tokens.test.ts) and [visual-contract.test.ts](../../../../pwa/src/test/visual-contract.test.ts) (`LEGACY_ERA_ALLOWLIST` is empty). ## Decisions and Tradeoffs

1. **Semantic CSS custom properties (`:root` vs. `:root[data-contrast="high"]`) + Tailwind v4 `@theme inline`, keeping raw numbered ramps immutable:**
   - **Choice:** Leave all numbered ramp stops (`charcoal-50..900`, `terracotta-50..900`, `ochre-50..900`, `sage-50..900`, `cream-50..500`) strictly monotonic and unchanged. Introduce CSS custom properties in `:root` (Standard AA) and `:root[data-contrast="high"]` (High Contrast AAA) and bind them in `@theme inline` so Tailwind utility classes resolve dynamically at paint time without JS re-renders:

- `--role-nav-bg` / `--role-nav-border`: `.glass-nav` keeps translucent `rgba(253, 252, 240, 0.85)` + `blur(20px)` in Standard and switches to opaque `#FDFCF0` (`bg-cream`), `#6E645B` top border, and `backdrop-filter: none` under `:root[data-contrast="high"]`.
- **Alternative rejected:** Overriding `--color-terracotta-700` or `--color-charcoal-500` inside `[data-contrast="high"]` breaks monotonic raw ramps, causes non-linear jumps wherever numeric stops are used directly, and forces every raw token test to account for mode-shifted stop values. Mirroring the semantic token keys in `tailwind.config.ts` preserves parity with `tokens.test.ts` without colliding with any `visual-contract.test.ts` rule.

2. **Pure contrast resolution helper (`pwa/src/lib/contrast.ts`) + `ContrastProvider` without cross-member `localStorage` leakage:**
   - **Choice:** Put resolution rules in one pure helper `resolveContrastMode({ hasLoadedMember, memberContrastMode, storedMode, osPrefersHigh })`:
     - When `hasLoadedMember` is true: an explicit `'standard' | 'high'` on the selected member wins (and mirrors to `localStorage` under `contrastMode` for flash-free reload); when `memberContrastMode` is `null` (unset), return `osPrefersHigh ? 'high' : 'standard'` and **remove** the `contrastMode` key from `localStorage`.
     - When `hasLoadedMember` is false (boot before family load, `/welcome`, `/onboarding`, or unselected Profile): return `storedMode ?? (osPrefersHigh ? 'high' : 'standard')`.
   - **Case-insensitive member matching:** `ContrastProvider` matches `selectedFamilyMemberId` case-insensitively (matching `useFamily.ts` and `IdentityValidator.tsx`) because cookies in E2E and browsers can carry uppercase GUIDs.
   - **Tradeoff vs. `LocaleProvider`:** `LocaleProvider` retains a sticky browser `localStorage` fallback when a member has `preferredLanguage: null` because browser language is explicit once chosen; for contrast, an unset member (`null`) MUST track `@media (prefers-contrast: more)`, so clearing `localStorage` whenever a loaded member has `contrastMode: null` prevents a prior member's `high` setting from leaking onto another member on switch or reload. All `localStorage` reads/writes guard against storage exceptions.

3. **Flash-free `beforeInteractive` boot script and hydration parity:**
   - **Choice:** Add an inline `<Script id="contrast-init" strategy="beforeInteractive">` in [layout.tsx](../../../../pwa/src/app/layout.tsx) (and matching pre-hydration attribute on `<html>` with `suppressHydrationWarning`) that evaluates `localStorage.getItem('contrastMode')` (`'standard' | 'high'`), falling back to `window.matchMedia('(prefers-contrast: more)').matches ? 'high' : 'standard'`, and sets `document.documentElement.dataset.contrast`. Update [profile-local layout](../../../../pwa/e2e/fixtures/profile-local/app/layout.tsx) with `<ContrastProvider>` so isolated unselected Profile E2E tests exercise the real provider seam.
   - **Alternative rejected:** Applying `data-contrast` only inside `useEffect` would cause a visible Standard-to-High flash on initial paint when reloading a `high` member or OS high-contrast browser.

4. **Database DDL & EF Core constraint parity:**
   - **Choice:** Add nullable `contrast_mode text` with `CONSTRAINT "CK_family_members_contrast_mode" CHECK (contrast_mode IS NULL OR contrast_mode IN ('standard', 'high'))` to [schema.sql](../../../../api/database/schema.sql) and idempotently (`ADD COLUMN IF NOT EXISTS` + `pg_constraint` guard) to [compatibility.sql](../../../../api/database/compatibility.sql), matching the `ToTable(..., t => t.HasCheckConstraint("CK_family_members_contrast_mode", ...))` mapping in [RecipeDbContext.cs](../../../../api/src/RecipeApi/Data/RecipeDbContext.cs).
   - **Note on quoted constraint name:** Quoting `"CK_family_members_contrast_mode"` in PostgreSQL SQL preserves exact Pascal/uppercase identifier matching with `FamilyMembers` EF configuration, following the existing `"CK_recipe_search_documents_index_status"` convention in both SQL files.

5. **Playwright `assertCookbookVisualA11y` `contrastLevel` option:**
   - **Choice:** Extend `CookbookVisualA11yOptions` in [visual-a11y-contract.ts](../../../../pwa/e2e/visual-a11y-contract.ts) with `contrastLevel?: 'aa' | 'aaa'` (default `'aa'`). Under `'aa'`, require `>= 4.5:1` ordinary text / `>= 3.0:1` large text; under `'aaa'`, require `>= 7.0:1` ordinary text / `>= 4.5:1` large text. Keep all existing callers defaulting to `'aa'` while adding explicit `'aa'` and `'aaa'` sweeps in `profile.spec.ts`.

6. **Designer guidance and visual reference SVG alignment (North Star & designer identity unchanged):**
   - **Choice:** Leave [creative-direction-north-star.md](../../../../docs/creative-direction-north-star.md) and [agent-designer-identity.md](../../../../docs/agent-designer-identity.md) untouched because both are principle-level documents that already target WCAG 2.2 AA without hardcoded tokens.
   - Update designer guidance ([visual-identity.md](../../../../.agents/skills/designer/visual-identity.md), [SKILL.md](../../../../.agents/skills/designer/SKILL.md) for dual-mode semantic role tokens and `assertCookbookVisualA11y` `contrastLevel: 'aa' | 'aaa'`, and [cookbook-surfaces-and-motion.md](../../../../.agents/skills/designer/cookbook-surfaces-and-motion.md) for semantic surface/button/switch/focus tokens, opaque High Contrast `.glass-nav`, and `'aaa'` checks) alongside [visual-language-reference.md](../../../../docs/visual-language-reference.md).

## First Observable Slice

Begin with the dual-mode token & shared primitive contract (`globals.css`, `tailwind.config.ts`, `Button`, `Navigation`, `SuccessCard`, `tokens.test.ts`, `visual-a11y-contract.ts`, plus designer guidance, `docs/visual-language-reference.md`, and visual reference SVGs), because every UI and E2E surface depends on the CSS variable contract. Next, wire the complete persistence vertical slice (`specs/openapi.yaml` → Kiota generation → PostgreSQL schema/compatibility → EF/API DTO/Service/Controller → `family.ts`/`familyStore.ts` → stateful `mock-api.ts`) verified end-to-end against both unit tests and real PostgreSQL. Finally, wire `ContrastProvider` + `beforeInteractive` boot script + `/profile` `ContrastSelection` + household surface migrations and verify both AA and AAA modes, reload persistence, OS fallback, and member switching in Playwright.

## State, Concurrency and Recovery

- **Client state & stale-response protection:** `ContrastSelection` calls `updateMemberPreferences(selectedFamilyMemberId, { contrastMode: choice })` when a member is selected, reusing `familyStore`'s optimistic update and `preferenceSaveGeneration` fence. Rapid clicks (`High contrast` → `Standard`) or concurrent saves cannot let an older response overwrite a newer choice.
- **Error rollback:** If `PUT /api/family/{id}/preferences` rejects, `familyStore` rolls back only `contrastMode` on that member without setting an error under a newly switched member, and `ContrastProvider`'s derived `resolvedContrast` immediately reconciles `document.documentElement.dataset.contrast` and `localStorage` back to the prior confirmed (or OS-resolved) mode. No misleading remote-save success status is shown.
- **Unselected member / pre-load state:** When `selectedMember` is absent (`null` or not yet loaded), activating a contrast button sets `localStorage` and local provider state directly without firing an API write.

## Persistence and Side Effects

- **Authoritative store:** PostgreSQL `family_members.contrast_mode` (`text`, nullable, default `NULL`).
- **Validation & invariants:** `FamilyService.UpdateFamilyMemberPreferences` trims and lowercases `contrastMode` when supplied, rejects anything other than `"standard"` or `"high"` with `ArgumentException` (`400 Bad Request`), and treats an update where all four preference fields (`browseViewMode`, `preferredLanguage`, `cookingViewMode`, `contrastMode`) are null/empty as invalid (`400`). PostgreSQL enforces `CK_family_members_contrast_mode` directly at the relational boundary (`SqlState 23514`). Omitted fields remain unchanged; `UpdatedAt` advances via `IClock.UtcNow`.

## Compatibility, Rollout and Reversal

- **Existing data & clients:** Existing rows receive `contrast_mode = NULL` on migration and resolve cleanly via `@media (prefers-contrast: more)` (`high` if set on device, otherwise `standard` AA default). `contrastMode` in `specs/openapi.yaml` is optional and nullable (`type: [string, 'null']`), preserving compatibility with existing preference payloads omitting `contrastMode`.
- **Migration order & reversal:** `compatibility.sql` adds `contrast_mode` and `CK_family_members_contrast_mode` idempotently before `sqldef` reconciles `schema.sql`. Reversal only requires reverting code and removing the nullable column (note that once upgraded, pre-upgrade `RecoverySnapshotService` backups are rejected by its exact schema-hash guard as expected for any additive schema change).

## User Experience

- **Profile hierarchy (`ContrastSelection`):** Placed directly below `LanguageSelection` on `/profile` using the exact same `rounded-3xl` section container, icon + sentence-case `<h2>` (`Contrast` / `Contraste`), and two `flex-1 min-h-12` `aria-pressed` buttons (`Standard` / `High contrast` in EN; `Standard` / `Contraste élevé` in FR) with `Check` icon (`data-contrast-check`), `focus-visible:outline-2 focus-visible:outline-offset-4 focus-visible:outline-hearth-ink`, and `scroll-mb-[calc(8rem+env(safe-area-inset-bottom))]`.
- **Dual-mode visual feel across household surfaces:** Migrating shared primitives (`Button`, `Navigation`, `SuccessCard`) and key surfaces (`ProfileDropdown`, `LanguageSelection`, `profile/page.tsx`, `SettingsPageContent`, `FamilyManagement`, `TonightMenuCard`, `TonightPivotCard`, `HomeSections`, `DiscoveryCard`, `discovery/page.tsx`, `DiscoveryToggleCard`, `RecipeDetailSheet`, `GroceryList`, `NonCookingDaySheet`) onto semantic role utilities restores calm Standard AA hierarchy (`charcoal` `#28231F`, `charcoal-500` muted copy `#6E645B`, `#B85542` primary Hearth CTAs, `#A44A37` secondary/danger/Dislike ink, cooled herb `#4E6E52` Garden CTAs/Like/celebration, `#856400` Sunlight voting/Discover, `.glass-nav`, `>= 3.0:1` subtle icon-only affordances) while preserving full AAA contrast (`>= 7.0:1` text/icons, opaque `bg-cream` bottom nav, crisp borders) under `High contrast`.
