# Design

## Context and Existing Ownership

This change follows `unify-recipe-browse-search`; its four deltas and completed tasks remain the behavior contract. `pwa/src/app/(app)/layout.tsx` marks Home, Discovery, Planner and Profile fluid, but omits `/recipes`. `Layout.tsx` therefore gives Recipes page-wide `px-4 md:px-6` and an inner max-width wrapper before `RecipesExperience.tsx` adds its own `px-6` content gutter. In a local browser the Recipes root began at x=16 CSS px on a 393 px phone and x=24 on 820/1180 px iPad; the list began at x=40 and x=48 respectively. The dock spanned the full viewport. The newer user-supplied phone capture also shows the constrained toolbar pushing Recycle bin to a second row. Removing only the outer inset would leave the list about 28 px from each phone edge, so the inner content gutter must change too.

`RecipesExperience.tsx` owns the shared toolbar and both presentations. Its expanded input currently has no placeholder or icon, a plain white pill and browser-blue focus. The former Search page at source identity `98938135` had a magnifier, localized `recipes.searchPlaceholder`, soft white/glass field, shadow, terracotta focus, Filters count and Results heading. `RecipeFiltersSheet` owns draft versus applied selections; the unified controller holds applied filters, preferences and shared Discovery/Go-To scope. `Navigation.tsx` uses `Search` for the Recipes dock item, while the toolbar also uses `Search`. `BrowseAllEmptyState.tsx` already uses Lucide `BookOpen`.

The canonical visual owners are `pwa/src/app/globals.css`, `docs/visual-language-reference.md`, `.agents/skills/designer/visual-identity.md` and the current Home, Planner and Profile components. They establish the cream canvas, warm light surfaces, sage selected state, terracotta action/focus vocabulary, Outfit headings and Inter body text. The local iPad render shows a two-column grid at 820×1180 and three columns at 1180×820; card bounds are useful and do not need to become edge-to-edge photographs.

## Decisions and Tradeoffs

1. **Fill the shell, bound the content.** Add `/recipes` to the existing fluid-shell selection instead of removing padding from the whole application. Replace the compounded phone insets in Recipes with one responsive content gutter: measure the outer surface at x=0 and viewport width, then the 390–393 px phone grid/content at 16–20 px from each edge. Let the toolbar occupy the available Recipes width before wrapping; at ordinary 393 px text its controls should fit when their measured widths permit, while French/200% text may wrap in order. On 820/1180 px iPad, use responsive 24–32 px gutters and retain two-column portrait, three-column landscape grid and bounded stack widths. This addresses the visible card width as well as the background without stretching cards to tablet width. Keep safe-area and dock-height logic; review short screens after the shell change.
2. **Restore Search hierarchy inside the unified disclosure.** Reuse the localized example placeholder, magnifier, soft white/glass surface, rounded field and modest depth from former Search. Use a visible terracotta focus treatment with sufficient contrast rather than browser-blue or the former faint placeholder opacity. Restore a Filters count pill and accessible count description using the existing applied-value semantics: selected array entries, true booleans, Focus concepts and each selected shared scope once. Do not count text, Similar, dismissed chooser drafts or duplicate copies of Go-To/Discovery.
3. **Keep results ordinary.** Show a quiet Outfit/Inter Results heading only above a nonempty Search list. Stack already has a position label and limited vertical room; loading and empty recovery keep their own primary message. Preserve the shared 4:3 grid, stack cards, result order and former topPick exactly once as an ordinary card. Do not restore the retired spotlight, reasons or random promotion.
4. **Distinguish destination from action.** Use existing Lucide `BookOpen` for the dock Recipes item while leaving its text, route, active terracotta state, touch target and `aria-current` behavior intact. The toolbar magnifier remains Search. This uses an icon already present in the recipe library and adds no asset or dependency.

## First Observable Slice

Open `/recipes` from bottom navigation at 393×852 with a selected member. A test first observes the unwanted outer and compounded inner insets in the real app shell, then the implementation makes the outer surface span the viewport and starts the list content 16–20 px from each side. It measures toolbar width and wrapping while retaining 48 px targets, order and bottom-dock reachability. The seam is app route layout → shared `Layout` → `RecipesExperience` → fixed Navigation. Browser acceptance repeats outer/content edge measurements at 820×1180 and 1180×820, in list and stack, with loaded and empty states and 200% text; no API shape changes are involved.

## Compatibility, Rollout and Reversal

This is presentational and reversible. The Search POST request/cursor state, Explore GET page/history state, member presentation preference, planning and detail entry, hidden-control session preservation, departure reset, filters draft/Apply behavior and Discovery voting route remain unchanged. Existing mocks and fixtures continue to represent the same API. The current private preview can be rebuilt after implementation verification without resetting its seeded data or changing its tunnel, ports or authentication. No production deployment is part of this change.

## User Experience

The toolbar remains Search, All/Discovery, Go-To, Stack/List, Recycle bin in DOM and visual order, including wrapping at narrow widths. Every toolbar target remains at least 48×48 CSS px. Expanded Search keeps focus on the input; Escape and hide return it to the disclosure without clearing criteria. The terracotta dot and accessible active-search label remain only while a current Search is active and controls are collapsed. Localized placeholder and Filters/Results labels must fit French and 200% text without clipped controls, horizontal overflow or inaccessible recovery. Reduced-motion and safe-area behavior are retained. Compare rendered phone, iPad portrait/landscape and Home/Planner/Profile references using the designer skill; tests establish behavior and geometry, while rendered review judges hierarchy and visual fit.
