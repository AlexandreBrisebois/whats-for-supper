## Canonical and historical boundary

The current member-preferences contract and `specs/openapi.yaml` contain no telemetry preference/REST operation. Generated API models therefore require no telemetry-driven regeneration. Business save/import-report contracts remain authoritative. The six retired telemetry contracts must not be left as current promises. Preserve the existing active gesture change `restore-stack-card-gesture-reliability` and all its evidence/tasks; its unrelated completion is outside this proposal.

No dormant code is retained just because it is unwired: synthetic telemetry checks go too. No old archive is deleted just because it names Sentrame. No logging call is removed solely because its class or test includes “telemetry”. Final search results must be classified under these boundaries.
